# 桌面工具版本检查与升级

工具页统一使用“检查更新”：先刷新本机安装和接入状态，再读取已安装工具当前版本与官方公开最新版。登录恢复后启动一次；托盘或 Dock 重新打开主窗口再检查一次。重复检查合并为一个请求。普通焦点变化和 15 秒刷新只读取本地清单，不访问更新源。

## 版本规则

以当前版本和官方最新版比较是否有更新。列表与详情不再展示“已验证兼容版”“内置版本上限”或普通新版“待验证”。升级目标来自本次成功的官方版本检查，不能退回旧的内置安装版本。获取版本失败时清除升级缓存，明确显示检查未完成。

新安装方案中的固定版本只用于可复现的新安装，与已安装工具的升级判断分离。安装完成后立即检查官方最新版本。OpenCode V1 的接入格式与 V2 不同，DuMate 接入目前限定 1.0.89；仅这些真实的适配限制单独提示“接入适配需更新”，不泛化到其他工具。

## 原安装渠道

- 原生安装的 Claude Code、由客户端安装的 Codex：使用官方安装器安装检查到的具体最新版。
- npm 全局安装：读取实际包身份与原全局前缀，在同一前缀中更新官方包。不会因 CLI 通过 npm 安装就一律降为手动更新。
- Homebrew 安装的 Claude Code、Codex：使用原 cask/formula 更新。
- Hermes、客户端管理的 OpenClaw：使用工具官方更新命令。
- 客户端管理的 Pi、Oh My Pi、Kimi Code 独立程序：读取目标正式发行中的平台安装包及 SHA256 摘要，再使用原目录更新流程。校验信息不可用时保留已知版本信息并禁止执行，不退回旧的校验值。
- 图形应用和无法确认的其他安装渠道：显示“手动更新”，说明使用应用内或原包管理器更新，并提供官方入口。

查看官方指引本身不会执行升级。版本检查、安装与升级都不会接入工具或测试模型。

## 执行与恢复

确认窗口展示当前版本到检查到的最新版。前端传目标版本供核对；后端只接受自身缓存的官方目标和更新路线，不接受任意下载地址、命令或用户指定版本。执行前重新检查实际安装路径、渠道与版本，并在下载安装器后的变更步骤前再次拒绝降级。

安装、升级和接入共用工具级操作锁；DuMate 两种账号类型共享实体应用锁。升级使用原执行器，保留输出、进度、取消和重试。客户端管理的目录记录未完成状态；取消或失败后不能把只写出版本号的半成品认作有效安装。重试可恢复同一目标或更新的官方目标，不覆盖更高版本。原渠道包管理器采用其自身的安装恢复机制。

程序退出成功也需重新读取实际版本，达到本次目标才报告完成。Homebrew 和官方自更新器若在此期间更新到更高版本，保留并显示实际版本。凭据和连接记录不属于升级流程。

## 列表与全部升级

版本与安装列负责版本、安装和升级操作；接入状态列只描述连接。未安装且无连接时接入列显示“—”；已安装但无连接显示“未接入”。工具暂时缺失但已有连接记录时继续展示保存的连接状态。失败后的客户端托管升级可以显示“继续升级”。

“全部升级（数量）”只统计可直接升级的工具，不受列表筛选影响。确认后逐个执行；单工具明确失败后继续处理其他工具，无法确认原生状态时停止后续队列。支持停止当前操作并跳过剩余工具，原生安装器需在自己的窗口中取消。退出登录后不启动下一工具。DuMate 共用应用只检测和计数一次。

## 版本来源

Claude Code、Codex、OpenClaw、OpenCode、Grok Build、Pi、MiniMax Code、Kimi Code 使用官方 npm latest 元数据；Hermes 与 Oh My Pi 使用官方 GitHub 最新正式发行；WorkBuddy 使用官方历史下载页；DuMate 使用官方 Electron 更新元数据。独立安装包进一步检查对应官方 GitHub 发行的资源身份与摘要。

Harness CLI 使用官方 npm 元数据。Harness 桌面官方更新 YAML 在本次核对时返回 404，明确显示检查未完成，保留官网入口，不声称已是最新版。

请求只读取公开元数据，不发送账号或配置。并发上限 4，连接超时 4 秒、单请求超时 12 秒，响应上限 2 MiB，仅允许 HTTPS 重定向。单工具失败不影响其他工具。

Windows 后台执行器以 `CREATE_NO_WINDOW` 启动版本检测和安装辅助进程，超时/取消时的清理进程也使用同样设置。启动、手动检查和托盘/Dock 唤醒使用同一执行器。原生回归在没有父控制台的进程中调用真实执行器，验证 EXE、CMD 包装和 PowerShell 不分配控制台；普通控制台测试进程会掩盖这一问题。

## 本次验证

隔离安装器验证了当前版本高于旧安装版本时仍可升级最新版、原 npm 前缀更新、确切目标确认、官方资源与摘要校验、拒绝降级、取消恢复和错误结果。界面夹具验证列表、单工具及批量升级。只读实机检查识别 Claude Code 2.1.311 → 2.1.318、Codex 0.163.0 → 0.166.0 均可直接升级；没有实际执行本机工具升级或模型调用。

官方资料：[Claude Code 更新](https://code.claude.com/docs/en/setup#update-manually)、[OpenClaw 更新](https://docs.openclaw.ai/cli/update)、[Hermes 更新](https://hermes-agent.nousresearch.com/docs/getting-started/updating)、[Kimi Code 更新](https://moonshotai.github.io/kimi-code/en/guides/getting-started#upgrade-and-uninstall)。


## 安装方式与配置位置

已安装工具在列表中展示安装方式和当前识别的程序入口；多份安装可以展开查看，并标出当前入口。重复 PATH 条目及指向同一实际文件的别名不重复计数。不同的实际程序保留各自路径，当前入口遵循既有命令搜索顺序，不按版本号擅自切换。

安装方式由可见事实识别：官方 npm 包的 package.json、Homebrew 路径、桌面应用、原生文件格式或客户端管理目录。不明确的入口标为“命令行程序”。未安装工具展示当前平台实际安装方案，不套用其他产品的 npm 或脚本说明。目录发现只读取元数据，不执行其他候选程序。

详情“安装与配置”展示当前入口、符号链接实际文件、配置目录及本应用的接入配置文件。配置路径沿用接入代码的解析结果，尊重已有环境覆盖。文件未生成时明确说明，不创建目录、不读取凭据内容、不更改 PATH，也不删除或切换现有安装。
