# 千问办公（QwenWorkCN）

工具 ID 为 `qwenwork`。桌面端“一键接入”和 CLI 共用外置 worker 与本地代理方案：

```sh
tokenmarket connect qwenwork
tokenmarket reconnect qwenwork
tokenmarket disconnect qwenwork
```

先安装并登录千问办公。接入、重新接入和取消接入可以在千问运行时保存配置，不要求先退出，不自动退出或重启。保存后只读检测主程序与后台：仍运行时提示“已保存，重启千问办公后生效”，提供“重启千问办公”和“稍后手动重启千问办公”；未运行时只提示“已保存，下次启动千问办公时生效”，不显示重启按钮。检测失败不影响已保存配置，提示用户按实际运行状态退出后重新打开。接入会准备外置 worker、原生本地代理和模型目录；不需要 Python，不修改 `app.asar`、应用包或厂商签名，不重新打包千问。下次启动后选择 `Token Market · …` 模型。

保存和重启是独立操作。用户点击重启后，请求千问正常退出，任务中断确认、未发送草稿和任务收尾均交给千问自己的原生退出流程；空闲时也可能出现该确认。不读取或注入内部任务状态，不扫描私有任务实现或依赖固定应用版本，不绕过原生确认，不强杀进程。确认主进程与后台完全退出后再打开；用户取消退出、退出未完成或无法可靠确认进程身份时，不重复打开，已保存的配置保留。千问已经退出时直接打开。

macOS 使用 AppKit 正常终止请求，按应用路径、Bundle ID、PID 和启动时间核对实例。Windows 使用当前用户、安装路径、PID 和启动时间定位实例，请求原生窗口关闭；若窗口关闭策略只是隐藏到托盘或应用拒绝退出，停止自动重启并提示手动完全退出。Windows 尚未完成真机退出确认验收。

升级、降级或重新安装千问办公后，返回 Token Market 点击“重新接入”，保存后重启千问。程序按当前安装重新生成外置 worker、本地代理、模型目录和加载配置；托管配置丢失或被改成其他值时直接覆盖，无须先取消接入。保留用户其他模型、聊天和其他设置。重装后尚未登录初始化的客户端，需要先登录。

接入不按应用版本号或单一 SDK 文件指纹限制。程序检查应用是否保留外置 worker 加载接口、数据库结构和 SDK 路由契约；动态识别混淆后的函数名，再用千问自带 Node 执行离线自检。自检只使用虚拟凭据、虚拟模型和本机接口，禁止远程联网，验证策略解析、占位凭据校验、模型组装、流式工具调用及结果回传；不读取真实 API Key，不调用计费模型，不依赖系统安装 Node/Python。

接口结构兼容且自检通过的新 SDK 可直接接入，无需先发布新版 Token Market。接口变化、外置加载机制消失或自检不通过时，统一提示“当前安装的千问办公尚未适配本地接入方案，请联系管理员适配；原连接和凭据已保留”。此时不签发 Key、不改模型和加载配置。不能保证结构发生重大变化的未来 SDK 自动适配。

已核对当前 macOS 1.5.0（26110307）自带 SDK 1.0.53 / worker 1.1.71，以及官方 worker 1.1.60、1.1.69、1.1.70、1.1.71 的发布构建。上述构建通过相同的本机流式工具调用自检。1.1.71 的 Windows x64 worker 脚本与该版本 macOS 脚本指纹相同，也经过脚本自检；这不代表 Windows 原生客户端已完成验收。官方构建来源及指纹见 [兼容性核对记录](qwenwork-sdk-compatibility.json)，不随工具分发原始 SDK。

## 请求与凭据

主对话代理原样保留 SDK 的原生 `session-id`，由网关兼容读取；桌面辅助代理使用会话专属回环地址恢复 ID，再通过 `X-Session-Id` 交给网关。范围、生效步骤和验证见[Agent 会话 ID](session-ids.md)。

会话窗口有两条模型通道，都需要接管：主对话、SDK 子任务和自动审查经过“千问外置 worker → 本机原生代理 → Token Market 网关”；桌面主进程发起的提问建议、会话标题、摘要等辅助推理经过“桌面辅助模型客户端 → 本机桌面代理 → Token Market 网关”。只添加 BYOK 主模型不能接管第二条通道。

桌面代理通过 `ENGINE_MAAS_MINT_URL` 接管模型服务凭据签发，返回随机本地访问令牌和回环地址。千问原有签发请求携带的官方登录凭据不保存、不转发；真实平台 API Key 仍只由原生代理附加到发往已配置网关的 Authorization，worker 和桌面辅助模型客户端都不持有真实 Key。修改签发入口也会改变千问的凭据缓存作用域，旧官方模型凭据不会沿用。

SDK 的系统模型、子任务和审查调用即使没有 BYOK 标记，也改走本地代理。桌面辅助模型的 `lite`、`flash` 等官方别名映射到连接中保存的辅助文本模型；重新接入时该模型仍可用就保留，首次接入或模型不可用时优先使用客户端指定默认模型，再按模型 ID 稳定选择，不依赖目录返回顺序。显式平台模型 ID 保留。支持 Chat Completions、Responses 和 Messages；不支持的接口在进入本地中继时明确失败，不退回官方模型。原生进程回退的模型网关指向保留的无效域名，防止绕过外置 worker 后继续产生官方推理费用。托管 worker 的 `openapi` 和 `center` 控制接口使用 SDK 原有默认或选举地址，保留账号认证与控制请求；推理、安全推理和搜索回退不放开，用户显式配置的其他地址也不改写。

接入前创建的旧任务恢复时，会通过宿主任务令牌重新查询 `/api/v1/userinfo`。该认证请求不能使用模型推理的拦截地址，否则会在推理开始前报 `ENOTFOUND tokenmarket.local.invalid`。2026-11-06 修复这条认证路径；不修改或删除历史任务。安装包含修复的新客户端后，需要重新接入并完整重启千问，使外置 worker 更新。离线自检使用实际 SDK 的任务令牌初始化、账号请求方法和端点解析器，验证认证后携带旧消息继续走本机模型代理；全部使用虚拟令牌和本机 HTTP 夹具，不代表真实旧任务已经实机验收。

- 真实 Key 保存在 `~/.tokenmarket/desktop-connections/` 的 AES-256-GCM 加密记录中，主密钥由系统凭据库保管。备份和连接收据也加密。
- 千问的 `byok_custom_models` 只保存 `tokenmarket-local-v2:<SHA256 fingerprint>` 占位符。`plainBase64` 仅包装这个非秘密标记，里面没有真实 Key。
- 模型 URL 使用 `https://tokenmarket.local.invalid/v1/chat/completions` 作为本地路由标记，不向这个域名发请求。
- 外置 worker 使用 SDK 原有传输和 SSE 解码器，保留流式文本、工具调用及取消信号。每个 worker 启动原生代理，从私有标准输出获得随机回环端口与短期访问令牌；令牌只用于本机代理。
- 代理仅监听 `127.0.0.1`，校验访问令牌、Host、请求路径及连接模型目录，拒绝浏览器 Origin，不使用千问进程的 HTTP 代理，不跟随上游重定向。上游错误使用通用文案，正常响应中意外回显的完整 Key 也会过滤。
- 代理启动时核对当前保存的连接、环境与配置证明。已启动的代理在内存保留其原连接，保存新的接入或取消接入不会通过代理强行中断已有任务；worker 退出后其代理停止，新代理必须校验新的保存状态。
- 桌面代理由多个 worker 共用，随千问宿主进程退出而停止。它校验回环 Host、随机访问路径及令牌，拒绝浏览器 Origin。新代理只接受重新接入后保存的新令牌；已运行实例的旧令牌随原进程结束而停止。
- 辅助代理启动失败只影响使用该入口的桌面辅助请求，不终止 SDK worker。主对话与 SDK 子任务继续通过各自的原生本地代理访问平台；辅助请求仍指向本机，不改回官方模型。路由配置本身损坏时仍明确要求重新接入。

这是应用间的数据流隔离，不是对同一用户权限下恶意本机程序的安全沙箱。千问登录、同步、模型目录、余额查询等业务功能仍访问官方服务；模型推理与这些业务请求分开处理。历史方案已经发送的数据无法由迁移撤回，曾经写入或发送过的旧 Key 可由用户在平台重置。

## 文件与迁移

- macOS 模型库：`~/Library/Application Support/QwenWorkCN/data/agents.db`。
- Windows 模型库：`%APPDATA%/QwenWorkCN/data/agents.db`。
- 设备配置：`~/.qwenworkcn/.env`，管理 `ALLOW_CUSTOM_BYOK`、`QW_QODER_WORKER_RUNTIME_PATH`、`ENGINE_MAAS_MINT_URL`、`TOKENMARKET_QWENWORK_ROUTE` 和 `QODERCN_SERVER_ENDPOINT`。取消接入恢复接入前的值，保留其他变量。
- 桌面路由文件：新连接使用设备目录的 `tokenmarket-desktop.tokenmarket.json`；旧连接沿用恢复收据记录的路由文件路径，不随 SDK/代理版本目录变化。保存回环端口、随机本地访问令牌、Key 指纹及辅助模型 ID，不含真实平台 Key，与模型库、设备配置一起事务写入和恢复。
- 外置运行时：`~/.qwenworkcn/tokenmarket-local-sdk-v2/<SDK、代理程序、环境指纹>/`，由客户端复制当前安装 SDK 的必要资源和自身原生代理，不随仓库分发千问 SDK。

只导入 Key 可见且有 `TEXT_GENERATION` 能力的模型。保留用户的其他模型、默认选择、会话及其他数据库表；模型库使用 SQLite 事务和行快照，不用整库覆盖。接入自身不产生推理，主动测试或实际对话可能产生费用。

重新接入会移除旧的 `byok-tokenmarket-` 托管模型，并用占位凭据重建目录。每次从当前安装重新写入生成的运行时文件，可修复外置 worker、原生代理或资源损坏。写入时启用 SQLite `secure_delete`，取消接入不把旧真实凭据恢复回千问数据库。模型目录和设备配置共同受回滚保护；重新接入覆盖托管字段，取消接入仍对接入后的人工修改提示恢复冲突。外置运行时目录保留供已启动进程安全退出，取消接入会恢复加载路径。

数据库兼容检查按实际管理的列及其类型、主键检查，不要求列的顺序完全相同。新增可空列、有非空默认值的列和生成列可继续使用；更新已有托管模型不覆盖这些原生字段。不认识的必填且无可用默认值字段、核心字段改名/类型变化或主键变化仍在写入前拒绝。该兼容方式不修改数据库结构，不能保证执行接口发生变化的未来版本可直接使用。

macOS 的真实 SDK 策略解析、模型组装、调度、HTTP/SSE、两轮工具调用和结果回传有本机端到端测试；代理还验证了错误令牌、浏览器来源、越权模型、连接撤销与跨流分片 Key 回显过滤。测试使用虚拟 Key，不把真实 Key 交给 SDK：

```sh
cargo test --manifest-path rust/tokenmarket-core/Cargo.toml --lib qwenwork_relay
cargo test --manifest-path rust/tokenmarket-core/Cargo.toml --test qwenwork
```

Windows 有路径与配置离线测试，尚未完成外置 worker 真机验收。接口文本测试或基本真实对话不代表所有桌面 Agent 工具能力均已验收。本轮处理文本会话接入，按用户决定暂不处理生图和视频。它们可能通过独立的 `openapi-v1` 厂商通道，也可能进入当前未支持的媒体接口；不承诺接管、可用性或停止官方计费。未知接口只有实际进入本地中继才会报错，不能据此断言其他厂商出口已被阻断。

当前不改应用包、不注入桌面主进程、不改厂商任务调度、不开启模型热切换。配置持久化使用 SQLite 行事务及文件冲突/回滚检查，可与 WAL 读事务并存；完整重启后由千问重新加载。重启前已运行的任务及代理可能继续使用原模型、账号/空间和费用归属，不能把“配置已保存”显示成“运行配置已生效”。厂商运行时自行重新读取的条目不属于热切换承诺。未来若某个文本入口必须新增深改，应先说明具体变化和影响，由用户决定。

2026-11-06 增加桌面辅助通道及 SDK 无 BYOK 标记调用的离线回归。测试直接从本机安装包读取桌面 `UtilityModelClient.send`，在千问自带 Node 中通过原生代理向本机虚拟上游发送提问建议、标题、摘要、审查和子任务请求；禁止远程网络，使用虚拟凭据。另覆盖 Responses/Messages 路由、已保存变更不打断已运行代理、新进程禁止复用旧令牌、取消接入及恢复。这些是离线验证，不代表真实会话和官方积分账单已完成验收；现有连接需要使用包含本次改动的新客户端重新接入并重启千问。保存与重启交互、代理故障隔离和兼容性回归见 [验收记录](acceptance/2026-11-06-qwenwork-save-restart.json)。
