## What to build

当同一范围通过 CLI、桌面或重复平台请求同时发起迁移时，所有成功请求收敛到
同一个新 Key；数据库失败不会留下部分迁移，过期请求不会覆盖新状态或影响
其他范围。用户最终看到一条新规则 Key 及完整保留的历史 Key。

## Acceptance criteria

- [ ] 同一旧规则范围的并发迁移只创建一个新规则 Key 记录，成功请求返回或复用同一个 Key ID。
- [ ] 新 Key、配置记录、绑定和规则采用状态在现有事务及范围并发控制下保持一致；任何一步失败均不会留下部分提交。
- [ ] 同设备 CLI 与桌面的并发连接遵循既有跨进程操作锁，最终配置不互相覆盖，平台在独立并发请求下也保证唯一签发。
- [ ] 迁移期间落后的旧凭据、旧确认或重复请求不能把绑定切回历史 Key、回滚已采用的新状态，或停用历史 Key。
- [ ] 接入期间登录或 Current Workspace 已改变时，过期操作不能发布错误归属的配置，并保留既有配置。
- [ ] 不同账号、空间、设备、Tool、客户端身份和服务地址范围不会被错误合并；同名 Key 不作为锁或唯一范围。
- [ ] 真实 PostgreSQL 集成测试覆盖并发旧范围迁移、事务回滚及重试，断言实际记录数、绑定和历史 Key 原值；内存夹具不代替数据库保证。
- [ ] 客户端连接入口测试覆盖并发操作及失效上下文，证明最终配置使用正确的新 Key，之后继续复用。
